# 基金搜索与即时查询设计

## 目标

在“市场扫描”中提供清晰的基金搜索入口。用户输入“创业板ETF”或六位基金代码时，可以从真实基金数据中看到候选项；点击候选项后立即按基金代码查询并刷新行情列表。

## 交互设计

- 将现有关键词输入升级为 Mantine `Autocomplete`，保留自由输入与回车查询能力。
- 输入至少 2 个字符后，延迟 250ms 请求候选项，减少连续输入产生的无效请求。
- 每个候选项展示基金名称、六位代码、场内/场外和基金类型，最多展示 8 条。
- 点击候选项后，将查询条件切换为 `matchBy: "code"`，并立即执行行情查询。
- 用户继续编辑文本时，将匹配字段恢复为 `all`，避免代码精确匹配阻断名称搜索。
- 搜索建议加载、无结果与接口异常均在下拉层内反馈，不改变表格尺寸，不清空当前行情。
- 原有快捷主题、匹配字段、市场、排序和数量筛选继续保留。

## 数据链路

1. React 输入框收集搜索文本并执行 250ms 防抖。
2. 前端请求 `/api/funds`，使用 `matchBy=all`、`sort=name`、`limit=8` 获取候选基金。
3. 服务可用时使用实时 API；服务不可达时，从 Pages 导出的真实基金快照中筛选候选项。
4. 用户选中候选项后，以六位代码调用现有行情查询链路。
5. MCP/Bridge 返回基金行情后，列表与行情概览按现有逻辑更新。

## 状态与错误处理

- 每次新建议请求会取消上一请求，防止旧结果覆盖新输入。
- 少于 2 个字符、输入为空或选中查询后不请求建议。
- 建议请求失败时保留用户输入和当前行情，并显示“暂时无法获取搜索建议”。
- 行情查询沿用现有加载进度、错误弹窗和静态真实数据兜底。

## 响应式要求

- 桌面端候选项保持名称为主、代码与类型为辅的两层信息结构。
- 手机端候选层不超出视口，基金名称允许省略，代码与市场标签保持可见。
- 搜索触发不改变表格表头、市场扫描卡片或右侧行情概览的位置。

## 验收标准

- 输入“创业板ETF”能显示匹配的真实基金候选项。
- 点击任一候选项后立即刷新列表，结果包含选中的基金代码。
- 输入六位代码能显示并精确查询对应基金。
- 快速连续输入不会出现旧建议覆盖新建议。
- 实时接口故障时，Pages 站点仍能通过真实快照搜索。
- 桌面和手机视口均无布局跳动或候选层溢出。
